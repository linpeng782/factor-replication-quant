# SGD 数学原理：从一个 batch 到全量梯度

> 写给"训练入门"读者。基于本项目（ml_ht，alpha158 +  StockMLP）真实数字推导。
> 配套代码：`ml_ht/train.py:35-39`（训练五步）、`ml_ht/dataset.py`（数据切分）。

---

## 0. 符号约定

| 符号 | 含义 |
|---|---|
| N | 训练集总样本数（本项目 3,805,414） |
| M | batch 大小（本项目默认 8192） |
| K | 一个 epoch 的 batch 数（K = N / M ≈ 465） |
| L_all | 全量 loss：在全部 N 个样本上算的 loss |
| L_batch | 某一次抽的 M 个样本上算的 loss |
| grad_L_all | L_all 对权重的梯度（14,361 维向量） |
| grad_L_batch | L_batch 对权重的梯度 |
| grad_BCE_i | 第 i 个样本单独贡献的梯度（单样本反传一次得到的向量） |
| E[·] | 期望，理解为"多次重复抽样的平均结果" |
| Var[·] | 方差 |
| ∝ | 成正比 |
| Σ | 求和符号 |

## 2. 训练五步逐行解释

`train.py:35-39` 是核心：

```python
pred = model(X_batch)              # ① 前向：用当前权重算 8192 个预测值
loss = criterion(pred, y_batch)    # ② 算 batch loss（BCE 平均）
optimizer.zero_grad()              # ③ 清掉上次的梯度
loss.backward()                    # ④ 反传：算 14,361 个偏导数
optimizer.step()                   # ⑤ 更新：W_new = W_old - lr × 梯度
```

### ① 前向（model.py:15 StockMLP）

数学上：

```
h1 = tanh(W1 @ x + b1)        # 158 → 80，W1 是 80×158 矩阵
h2 = tanh(W2 @ h1 + b2)       # 80 → 20
logit = W3 @ h2 + b3          # 20 → 1
pred = sigmoid(logit)          # → 0~1 概率
```

W1 + W2 + W3 + b1 + b2 + b3 = 14,361 个数，一开始随机（Xavier 初始化，`model.py:30`）。

### ② 算 loss

`criterion = BCEWithLogitsLoss()`（`train.py:71`），默认 reduction='mean'，对一个 batch 内 M 个样本取平均：

```
L_batch = (1/M) · Σ_{i∈batch} BCE(pred_i, y_i)
```

具体例子：模型预测某只股票涨概率 pred=0.3，真实 y=1（确实涨了）：

```
BCE(0.3, 1) = -log(0.3) = 1.20           # 错得多
BCE(0.9, 1) = -log(0.9) = 0.105          # 错得少，loss 就小
```

### ④ 反向（loss.backward()）

就是高数里的链式法则。Loss 是 14,361 个参数的函数 L(w₀, w₁, …, w_14360)。算它对每个参数的偏导数，得到一个 14,361 维向量——梯度。

举例：最后一层 logit = W3 @ h2 + b3，Loss 对 W3 某个元素的偏导：

```
∂L/∂W3[i,0] = (∂L/∂logit) × (∂logit/∂W3[i,0])
             = (pred - y) × h2[i]
```

直觉解读：
- (pred - y)：预测偏离真值多少，方向（要变大还是变小）
- h2[i]：第二隐藏层第 i 个神经元当时有多活跃
- 两者相乘 = "这个权重该往哪边调、调多大幅度"

### ⑤ 更新（optimizer.step()）

梯度指向 loss 上升最快的方向，我们要 loss 下降，所以**反着走**：

```
W_new = W_old - lr × grad
```

lr = 0.001（`train.py:92`），是步长。太大跨过最低点，太小慢得要死。

Adam 加分项：不是简单 `W - lr × grad`，而在每个参数上**单独维护一个动量 + 自适应步长**——最近梯度同向就加速、忽左忽右就减速，14,361 个智能独立小步走。

## 3. 损失是平均

### 全量 loss

```
L_all = (1/N) · Σ_{i=1..N} BCE(pred_i, y_i)      N = 3.8M
```

### batch loss

```
L_batch = (1/M) · Σ_{i∈batch} BCE(pred_i, y_i)   M = 8192
```

### 关系

shuffle=True 下，batch 是从训练集里均匀随机抽的 M 个样本：

```
E[ L_batch ] = L_all
```

batch 越大越接近 L_all；batch = 全量就完全相等；batch 太小（比如 1）波动大但期望不变。

---

## 4. 梯度也是平均（核心）

因为求导是线性运算，可以和求和交换顺序：

```
grad_L_all = d L_all / d w
           = d/dw [ (1/N) · Σ_i BCE_i ]
           = (1/N) · Σ_i  d/dw [ BCE_i ]
           = (1/N) · Σ_i  grad_BCE_i
```

同理：

```
grad_L_batch = (1/M) · Σ_{i∈batch}  grad_BCE_i
```

**关键事实**：全量梯度 = N 个样本逐样本梯度的平均。batch 梯度 = 这 M 个样本逐样本梯度的平均。

---

## 5. "全量梯度 = 每个 batch 梯度的平均" 的精确含义

把 N 个样本按时间分成 K 个不重叠 batch（每批 M 个），N = K · M：

```
grad_L_all = (1/N) · Σ_{i=1..N} grad_BCE_i                              # 全量

           = (1/K) · Σ_{k=1..K} [ (1/M) · Σ_{i∈batch_k} grad_BCE_i ]    # 拆开求和

           = (1/K) · Σ_{k=1..K} grad_L_batch_k                          # 就是 batch 梯度再平均

           = 平均(所有 batch 梯度)
```

**精确含义**：N 个样本的逐样本梯度求和，可以分两步走——先按 batch 求平均、再对 K 个 batch 求平均，结果完全相等。

---

## 6. "batch 梯度是真梯度的带噪声估计" 的精确含义

shuffle=True 下，每 epoch 重新随机分 batch，相当于从 N 个样本里随机抽 M 个算梯度。这时 batch 梯度是个**随机变量**：

```
E[ grad_L_batch ] = grad_L_all                    # 期望上等于真梯度
Var[ noise ] ∝ 1/M = 1/8192                       # 方差和 batch_size 成反比
```

- batch 越大 noise 越小（越精确）
- batch = 全量时 noise = 0（精确等于真梯度）
- batch = 1 时 noise 最大（每步梯度完全由单个样本决定，最噪）

写成加法形式：

```
grad_L_batch = grad_L_all + noise
```

noise 方差 ∝ 1/M。

## 7. 我们项目的具体例子

训练集 N = 3,805,414，batch M = 8192，一 epoch K = 465 个 batch。

盯最后一层权重 W3[0,0]（`model.py:22` `nn.Linear(20,1)` 的某个权重），初始 Xavier 初始化成 0.123。

### 全量做法（不实际用）

把 3.8M 样本一次性喂模型，算一个 L_all，反传一次得到：

```
grad_L_all 对 W3[0,0] 的分量 = +0.0442
```

意思："这个权重若稍增，全市场平均 BCE 会涨，方向应该减"。更新一步：

```
W3[0,0] 新值 = 0.123 - lr · 0.0442
             = 0.123 - 0.001 · 0.0442
             = 0.1229558
```

一个 epoch 调一次，需要把 3.8M 样本全过一遍。

### 实际用的小批量做法

一个 epoch 调 465 次。

Batch #1（8192 个样本，比如 2010-01-04 ~ 2010-01-05）：

```
grad_L_batch 对 W3[0,0] 的分量 = +0.0451   # != +0.0442，差 +0.0009 = noise_1
W3[0,0] ← 0.123 - 0.001 · 0.0451 = 0.1229549
```

Batch #2：

```
grad_L_batch 对 W3[0,0] 的分量 = +0.0418   # noise_2 = -0.0024
W3[0,0] ← 0.1229549 - 0.001 · 0.0418 = 0.1229131
```

…

Batch #465 调完后，W3[0,0] 走到比如 0.118（等价于全量走了 15 步的距离，但只用了 1/465 的全量计算）。

### 对比

| 方案 | 一个 epoch 调几次 | 一步方向 | 总位移 | 计算量 |
|---|---|---|---|---|
| 全量梯度 | 1 次 | 精确（无 noise） | 小 | 高（3.8M 全过） |
| Mini-batch SGD | 465 次 | 带噪声但期望正确 | 大 | 低（每步只过 8192） |

465 次小步 vs 1 大步：噪声每次方向不同（+0.0009, -0.0024, ...），期望上相互抵消，但累积位移指向真梯度方向。SGD 净效果：步数多得多 + 噪声做低通滤波 → 收敛更快 + 跳出 sharp minima 更鲁棒。

## 8. 为什么噪声不会让模型越走越瞎

因为 Adam 是带低通滤波的（`train.py:92`）。Adam 在每个参数上维护"最近几步梯度的指数滑动平均"m_t（一阶动量）：

```
m_t = beta · m_{t-1} + (1-beta) · grad_L_batch_t
```

beta 默认 0.9，所以 m_t ≈ "最近 10 步梯度的加权平均"。Adam 用 m_t 更新权重：

```
W_new = W_old - lr · m_t / (adaptive_step_size)
```

每步 noise_k 在 10 步平均里被稀释一半以上，信号（真梯度）保留。噪声不会累积发散，被 Adam 平滑掉了。

## 9. 一个 epoch 真实发生的事

```
[Epoch 5]
├── train_one_epoch:
│   ├── batch 1:   8192 样本 → 算 grad → 改权重 (~300ms)
│   ├── batch 2:   8192 样本 → 算 grad → 改权重
│   ├── ...
│   └── batch 465: 8192 样本 → 算 grad → 改权重
│   小计: ~5 min,  3.8M 样本全部过一遍, 改 465 次权重
├── evaluate(valid):      ← model.eval() 关 Dropout，不改权重
│   ├── batch 1:   8192 → 只算 loss 不反传 (~100ms)
│   ├── ...
│   └── batch 183: 8192 → 只算 loss 不反传
│   小计: ~30s,    1.5M 样本只评不改
│   循环结构同训练，缺 backward+step 两步
├── 算 IC / ICIR / L-S（10s）          ← history.jsonl 那一行
├── 写 history.jsonl（10ms）
└── 决定：是否 best？是否早停？
```

### 训练 vs 验证 的 batch 循环对比

| | 训练 `train_one_epoch` | 验证 `evaluate` |
|---|---|---|
| 算 batch loss（BCE mean） | ✓ | ✓ |
| 累加 `total_loss += loss × size` | ✓ | ✓ |
| 输出 `total_loss / total`（全集 mean） | ✓ | ✓ |
| backward + step（改权重） | ✓ 有 465 次 | ✗ 0 次 |
| `model.train()` / `model.eval()` | train（开 Dropout） | eval（关 Dropout） |
| shuffle | True | False |
| batch 循环次数 | 465 次 | 183 次 |
| 改权重次数 | 465 次 | 0 次 |
| 整轮走几遍 | 每 epoch 1 次 | 每 epoch 1 次 |

**"一个 epoch 走 1 次" 指整轮 valid 跑过一遍 ≈ 一次 evaluate() 调用**，不是只算 1 个 batch。
精确表述：**1 epoch 内 = 训练改 465 次权重，随后 valid 的 183 个 batch 循环只累加 loss 不改权重，最后回汇总 1 个 val_loss 标量**。

### 为什么要分 batch 而不一次性跑全集

1. **显存装不下**：1.5M 样本 × 158 列 × float32 ≈ 1GB 输入；加上中间 80、20 维隐藏层激活和反向传播缓存，单 batch 算占用 ~100MB 显存。一次性 1.5M 样本 = 200 倍，几十 GB，A100 80G 悬。分批只占一个 batch 大小。
2. **要逐样本收集预测概率**：`train.py:67` 把每个样本 Sigmoid 后的概率存下来，后面要算 IC/ICIR/L-S 这些排序指标，截面统计必须逐样本保留顺序。1.5M 的概率数组分 batch 累加比一次性塞内存顺。
3. **数学上等价**：分 batch 累加 mean × size 先求和再除总数，和一次性 mean 完全等价。

## 10. 早停（patience）的真实曲线

```
val_loss
  ┌─╮
  │  ╲___
  │      ╲╲____                           ← epoch 12 best (val_loss 最低)
  │            ╲___╲___╲___╲___           ← patience 计时器累加
  │                              \╲
  └──────────────────────────────────→ epoch
                                ↑
                        epoch 12 + 15 = 27 触发停止
                        保留 epoch 12 的模型
```

`patience=15` = 模型连续 15 轮 val_loss 不创新低才停。太小一抖就停，错过 best；太大纯浪费时间。15 是个折中。

## 11. Epoch 串行与 wide minima（为什么越跑越收敛）

### 常见误区：epoch 不是并行的

容易误以为"每个 epoch 站在山的不同位置"是并行——其实 epoch 是**串行**的，下一个 epoch 起点就是上一个 epoch 终点。

```
       Epoch 1 起点                  走一步                走一步              ...
       (Xavier 初始化)               (改权重)               (改权重)
            ↓                          ↓                      ↓
   ┌───────────────────────────────────────────────────────────────────┐
   │  epoch 1: 改 465 次权重 → 走到位置 P₁                                │
   ├───────────────────────────────────────────────────────────────────┤
   │  epoch 2: 从 P₁ 出发，再把同样 3.8M 样本 shuffle 一遍，再改 465 次    │
   │           → 走到位置 P₂                                              │
   ├───────────────────────────────────────────────────────────────────┤
   │  epoch 3: 从 P₂ 出发，再走 465 步 → P₃                               │
   ├───────────────────────────────────────────────────────────────────┤
   │  ...                                                                  │
   │  epoch 27 (best): 从 P_26 出发，再走 465 步 → P_27                    │
   ├───────────────────────────────────────────────────────────────────┤
   │  epoch 28-42: 一直在 P_27 附近打转，val_loss 没创新低                 │
   │            patience 累加到 15 触发停止                                │
   └───────────────────────────────────────────────────────────────────┘
```

### 为什么越往后越能收敛到 "好" 的盆地

把 465 个 batch 的 465 个小步想成"绕着山打转、慢慢往低处挪"。

```
epoch 1:  起点 → 一步步往下，但噪声大，路径像醉汉
epoch 2:  继续往下，因为还在大坡度段，信号压过噪声
epoch 5:  已经下到某片"小山谷"附近，坡度变平，grad 信号变小，noise 比重上升
epoch 10: 进入这片山谷后坡度极小，每一步几乎都是在 noise 驱动下小幅震荡
...
epoch 27: 震荡到一个相对更低点（best）
epoch 28+: 噪声主导，进一步下探的概率 < 上跳的概率 → val_loss 反而开始抖动
```

两层机制叠加：

**① Adam 的 m_t（一阶动量）做了 EMA 低通滤波**

`m_t = 0.9·m_{t-1} + 0.1·grad_batch` 把噪声压下去，只用"最近 10 步的方向平均值"走。
多 epoch 累积，10 步尺度上的随机方向相互抵消，留下真梯度方向。
→ 不是越走越乱，信号保留，噪声稀释。

**② SGD 倾向于走到 wide minima 而非 sharp minima**

- sharp minimum = 狭窄深谷，周围梯度变化剧烈，进去容易再跳出来
- wide minimum = 平宽盆地，周围坡度平缓，模型在新数据上更鲁棒

Batch 噪声客观上**把模型从 sharp minima 里弹出来**（尖锐谷底噪声幅度大、容易翻出）；
进入 wide minima 后噪声反而维持在那里（坡度平、能稳住）。
→ 越往后越收敛到对泛化更友好的位置。

### 形象比喻：沙漏里的沙子

14,361 维的 loss 山，沙粒（模型）从随机高点往下滚：

```
初期：坡陡，滚得快、方向确定
中期：滚到山脚某片缓坡，速度变慢
后期：进入某片更平的盆地，沙粒在那里微震（噪声驱动的 Brownian wandering）
最终：沙粒静止在一片 wide basin 内
```

不是所有沙粒都能找到全局最优，但 SGD+Adam 的组合让它们倾向找到"足够平宽、对新数据鲁棒"的盆地。**这正是泛化的数学本质**。

### Best epoch 为什么不是最后一个 epoch

本项目实测 best epoch=27，patience=15 触发在 epoch 42：

```
epoch 27 之后模型进入 wide basin
epoch 28-42 在 basin 水位线上下抖动
val_loss 没再创新低 → patience 累加 15 次触发停止
最终保留 epoch 27 那个快照的权重
```

如果继续走（max_epochs=100），模型只是在 wide basin 里 random walk，
不会收敛到更好的位置——所以靠 val_loss 选 best，不是 epoch 越多越好。

**直觉**：1 个 batch 走的预期方向是"局部下行方向"，但这是当时位置看见的局部梯度。
到了 wide basin 里局部梯度近 0，但噪声还在，所以累积的随机游走不会保证进一步下降。

### 一个常见的反驳以及为什么不对

"epoch 长是过拟合，epoch 短是欠拟合" 不绝对：

- 训练集 loss 越往后越低（噪声下也能继续微降），但**这不意味着模型学到新规律**——可能是开始背训练集，**val_loss 反而抖升**。这就是为什么必须用 val_loss 决定 best，**训练 loss 信息量很低**。
- early stop 不是怕"训练不够"，是怕"开始背训练集 / 进入无聊噪声游走"，提前喊停留在 best 那个快照。

本项目日志里 epoch 30 后 train_loss 比 epoch 27 略低，但 val_loss 不降反升——
说明训练 loss 那点下降是无效的"绕来绕去"，stop 在 27 是最优时刻。

## 12. 总结一句话

```
N 个样本的真梯度 = N 个样本逐样本梯度的平均
按 batch 切也 = 先按 batch 求平均、再对 K 个 batch 求平均

shuffle=True 下：每个 batch 是随机抽样
  E[ batch 梯度 ] = 真梯度
  Var[ batch 梯度 ] ∝ 1 / batch_size

每个 batch 调一次权重 = 朝真梯度方向走一小步 + 加一点高斯噪声。
重复几百次，噪声被 Adam 平滑掉，位移累积成有效优化。

epoch 串行接力 → 越走越接近 wide basin → val_loss 抖动到最低点 = best snapshot。
之后多跑无效，early stop 保留 best 快照。
```
