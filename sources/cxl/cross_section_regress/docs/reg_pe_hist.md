# reg_pe_hist — 经历史增速调整的历史 PE 变化（情绪性估值）

> 类别：价值 | 方向：−1 | 研报基准：IC≈0.063, ICIR≈0.85

## 1. 因子定义

三个对数变量（各要求底数 > 0）：
- `log_yoy   = log(net_profit_mrq_0 / net_profit_mrq_4)` — 单季净利润同比
- `log_npttm = log(net_profit_ttm_0)`                    — 净利润 TTM
- `log_pe    = log(pe_ratio_ttm)`                        — PE_TTM

各按个股交易日序列做 60 日 diff，再两步嵌套截面回归：
1. `delta_log_yoy ~ delta_log_npttm` → 残差 `residual_1`（独立于 TTM 趋势的利润 surprise）
2. `delta_log_pe ~ residual_1`       → 残差 `reg_pe_hist`（无法被利润解释的估值情绪变化）

**经济直觉**：PE 异常上行且无利润支撑 → 高估 → 预期低收益，故 direction = −1。
两步残差化（而非一次性双 x 回归）刻意分离"利润 surprise"与"利润趋势"两层信息，
残差化顺序即作者的因果假设。

## 2. 复现结果（20160101–20251231, 2430 天, n=5×g=5）

| 指标 | 值 |
|---|---|
| direction | −1 |
| IC 5/10/20d | 0.0445 / 0.0522 / 0.0600 |
| ICIR 5/10/20d | 0.360 / 0.424 / 0.491 |
| 单调性 | 0.953 |
| LongShort 年化 / Sharpe | 23.38% / 2.11 |
| 覆盖 | raw 5385 列, 清洗后非空 8.71M |

与研报基准（IC 0.063 / ICIR 0.85）有差距，主因：filter 要求三字段同时 > 0，
天然不覆盖亏损股；且研报口径细节（去极值/行业中性化）未完全披露。

## 3. 关键洞察：TTM 字段名修订（2026-05-29）⭐

**原 spec 用 `net_profitTTM`（驼峰），本次修订为 `net_profit_ttm_0`（官方文档写法）。**

起因：早期复现时只试了无后缀的 `net_profit_ttm`（不存在 → 全 NaN），便误判"必须用驼峰
`net_profitTTM`"，并把该结论写进 AGENTS.md / prompts。**从未尝试带数字尾缀的
`net_profit_ttm_0`**——而那才是官方 get_factor 文档的规范写法（三大报表基础科目 =
蛇形 + `_ttm_n`；衍生比率 = 蛇形无数字如 `pe_ratio_ttm`）。

实证（同一快照，全市场 5549 股，2010–2026）：

| 对比 | 结论 |
|---|---|
| `net_profitTTM` vs `net_profit_ttm_0` | **≈ 但 ≠**：99.5% 单元相同，0.51%（66,545 单元 / 860 股）有意义差异；`net_profit_ttm_0` 覆盖多 37 万非空 |
| `revenueTTM`（驼峰） | **返回 None**，取不到数 → 照旧规则会静默全 NaN |
| 因子表现 A(驼峰) vs B(ttm_0) | 统计无差别：IC/ICIR/单调性/Sharpe 差异均在 0.5%~2% 噪声内 |

**结论**：切到 `net_profit_ttm_0` —— 表现无损、覆盖更全、字段定义文档化可审计，
彻底摆脱未文档化遗留别名（该别名对科创板等新股行为异常，如 688122 差 7 倍）。

**教训**：未文档化字段"能取到数"≠"取的是对的数"；调试遇到字段报错时，先查官方
命名规则表（基础科目要带 `_n` 尾缀），不要在第一个"能跑通"的别名上停下。

## 4. 米筐 TTM 命名规则的经济学本质 ⭐

为什么基础科目是 `net_profit_ttm_0`（带数字），而比率是 `pe_ratio_ttm`（无数字）、
且 `pe_ratio_ttm_0` 返回 None？**命名规则不是 API 随意约定，而是数据本身时间结构的反映。**

两类字段的"时间深度"来自**完全不同的轴**：

| | 时间深度来源 | 后缀语义 | 实证（000001, 2023, 242 交易日） |
|---|---|---|---|
| 基础科目 `net_profit_ttm` | **财报期次轴**（数据只在财报日跳变） | 数字 `_n` = 第几期财报（_0 最新 … _8） | **5 个台阶值**，跳变日 = 财报披露日（3/9 年报、4/25 Q1、8/24 中报、10/25 Q3） |
| 衍生比率 `pe_ratio_ttm` | **交易日期轴**（每天随价格流动） | 后缀只选分母盈利口径（ttm/lyr），**无期次概念** | **205 个不同值**，几乎日日变 |

**经济直觉**：
- `net_profit_ttm_0` = 最新财报的 TTM 盈利。两次财报间是常数（阶梯函数），要拿历史值
  只能按财报期次往回翻 → 故需数字尾缀 `_n` 索引"哪一期"。
- `pe_ratio_ttm` = 当日市值 ÷ 最新 TTM 盈利。**分母按"期"阶跳、分子按"日"连续流动**，
  比率天然锚定"当下"。历史深度由 get_factor 的日期范围提供，期次索引无处安放。
- `pe_ratio_ttm_0` 之所以无意义：把"第几期财报"这个只适用于阶梯式原始财务的索引，
  硬套到一个永远锚定当日价格的估值比率上——该维度在经济上不存在，故米筐未建此字段。

**推论（适用一整类字段）**：报表数据按"期"离散更新 → 带期次尾缀 `_ttm_n`；
估值/比率按"日"连续流动 → 仅口径后缀 `_ttm`。另：比率的"基础名 × 口径"组合
不保证都存在（如 `pe_ratio_lf` 返回 None——盈利是流量，无"最新一期资产负债表"口径，
LF 只对净资产等存量变量成立，故 `pb_ratio_lf` 有而 `pe_ratio_lf` 无），选定字段后须验证可取数。
