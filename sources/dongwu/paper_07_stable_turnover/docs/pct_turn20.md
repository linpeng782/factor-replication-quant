# pct_turn20 —— 换手率变化率因子 PctTurn20（东吴证券 2021-05-15 系列第七篇，原出系列第三篇）

## 1. 因子定义

$$\text{base40}_{i,t} = \frac{1}{40}\sum_{k=1}^{40}\text{turnover}_{i,t-k},\qquad
p_{i,t} = \frac{\text{turnover}_{i,t}}{\text{base40}_{i,t}} - 1,\qquad
\text{PctTurn20}_{i,t} = \frac{1}{20}\sum_{k=0}^{19} p_{i,t-k}$$

即：日换手率变化率 =「当日换手率 / 基准换手率 − 1」，基准 = 再往前 40 个交易日换手率均值；
取过去 20 日变化率的平均值，横截面市值中性化。`direction = -1`。研报 line 127-133。

**经济直觉**：不看换手率的绝对水平，只看**相对自己近期常态的放大倍数**。放量（相对 40 日常态）
= 情绪过热/资金出逃，未来跌；缩量 = 关注度回落但也无人抛压，未来涨。相比 Turn20 的好处是自动
消除了个股换手率水平的截面差异（次新股/小盘股天然高换手），坏处是丢掉了水平信息本身。

## 2. 研报歧义与工程选择（**本因子歧义最多**）

| 歧义点 | 研报表述 | 本仓选择 | 影响 |
|--------|---------|---------|------|
| **基准是否含当日** | 「再往前取 X 个交易日」（line 129） | **不含当日**：`rolling(40).mean().shift(1)` | 含当日会让分母自带当日冲击，把变化率往 1 压缩、削弱信号。这是本因子最关键的一个二义 |
| 基准是否随日滑动 | 图 4 示意图不清 | **每日滑动**（每个 t 用各自的前 40 日基准），而非 20 日内共用一个基准 | 若共用一个基准，因子退化为「20 日均换手 / 前 40 日均换手 − 1」，信息量大减 |
| X 取值 | 「X 暂时取为 40」 | 40 | 总窗口 61 个交易日 |
| 分母为 0 | 未说明 | compute 算子自动把 inf 转 NaN | 长期零换手（停牌整段）会被丢弃 |

## 3. 实现

`specs/pct_turn20/spec.yaml`，5 步：
`load_panel` → `rolling(mean, 40)` → `transform(shift, 1)`（剔除当日）→
`compute: turnover / turnover_base40 - 1` → `rolling(mean, 20)`。
raw shape=(4025, 5476)，2010-01-04 ~ 2026-07-31，非空 13,730,050（比 turn20 少 46 万，即 61 日
窗口的 warm-up 代价）。

### ⚠️ 踩坑记录：L3 增量的 warmup 被低估（本 spec 是第一个触发者）

`run.py` 的增量回读窗口由 `core/spec_resolver.py::max_warmup_window` 决定，它取 spec 里
**单个最大** window。本因子的链是 `rolling(40) → shift(1) → rolling(20)`，**真实 warmup
= 40+1+20 = 61 个交易日**，但 `max_warmup_window` 返回 40，回读窗口只有 40+10=50 个交易日。

后果：2026-05-27 → 2026-07-31 增量补数时，**前 5 个新交易日（2026-05-28 ~ 06-03）整天全空**
（每日非空数=0），且**不报错、不告警**，只能靠逐日覆盖率排查发现。

修复前 `max_warmup_window` 的 docstring 其实已预警过这个假设
（「若未来在同一链上**叠加**多个时序算子，真实 warmup 需按链求和」），本 spec 正是第一个叠加的。

**当次处理**：用 `--rebuild` 全量重算修复（截面计算便宜，几十秒）。

**✅ 已根治（2026-08）**：`max_warmup_window` 已改为**按依赖链求和**——沿 steps 传播
`w[col]` 符号表，并行链取 max、串行链求和，本因子的 W2 现在正确返回 **61**。
顺带发现旧实现的 `_ROLLING_ACTIONS` 漏了 `rolling_ts_regress` / `rolling_group_ratio`，
导致 apm 系 / hl_volume_surge 系 8 个因子的 W2 长期是 1（真实 20），已一并补上。
全仓 108 spec 回归：95 不变 / 13 变大 / 0 变小。验证见 `scripts/verify_warmup_window_fix.py`。

| ICIR 20d | +0.515 | +0.633 |

**与研报对照**：研报月度 IC -0.043、多空年化 21.85%、IR 1.82（2006-2021）；13 篇同因子延长到
2023 年为 -0.048 / 20.81% / 1.491。我们 17.57%、IC 0.041，方向和量级一致，且**同样是四个因子里
最弱的两个之一**——与研报「PctTurn20 整体效果不如传统换手率因子」（line 139）的论断吻合。

## 5. 非平凡洞察

1. **唯一一个「中性化后变差」的因子**：IC 5d 从 0.0438 掉到 0.0384（-12%），单调性从 0.730 掉到
   0.698，多空年化也小幅下滑。其余三个因子中性化后 IC 都是上升的。原因：PctTurn20 的构造
   （除以自身 40 日基准）**已经内生地做了一次个股自身标准化**，把市值/行业相关的水平信息消掉了；
   再做一次行业市值中性化就开始削真信号。→ 这个因子用 cleaned 版本反而更合适，是全仓少见的例外。
2. **单调性最差 + 换手最高，性价比最低**：52% 双边换手（是 turn20 的 2.1 倍）却只有 17.6% 多空
   年化。按 30bp 双边成本估算年化磨损 ~8.2pp，扣完只剩 9pp 左右，实盘边际价值很小。
   **结论：PctTurn20 不建议单独用，价值在于作为 STR 正交化的控制变量**（研报 line 175 正是这么用的）。
3. **研报 2020 后失效在我们的样本里得到印证**：研报 line 139/144 说 PctTurn20 在 2020/09 后大幅
   回撤、13 篇 line 144 进一步说「自 2020 年 1 月后选股能力大幅下降」。我们的评估区间
   2016-2025 有近一半落在这段失效期内，这解释了为什么我们复现值（17.6%）低于研报全段（21.9%）
   的幅度，比 Turn20/STR 的衰减更明显。
4. **基准长度 40 日是「慢基准」，这正是它的病根**（13 篇 line 148 的原话）：「PctTurn20 捕捉的是
   长期的变动趋势，其基准使用的是 40 日前的换手率，对于换手率变化的敏感性较低」。东吴自己在
   13 篇里把基准换成「昨日换手率」得到新变化率，再取 std 就是 GTR。→ 想改进这个因子，
   应该做 `pct_turn20__base5` / `__base10` 之类的短基准变体，而不是调 20 日窗口。

## 6. 改进路径

- `pct_turn20__base10`：把 40 日慢基准换成 10 日，测敏感度提升是否带来 IC 提升
- 作为控制变量参与 STR / GTR 的正交化（研报正统用法）
- 该因子换手极高，如进模型建议先做 5 日平滑降换手
